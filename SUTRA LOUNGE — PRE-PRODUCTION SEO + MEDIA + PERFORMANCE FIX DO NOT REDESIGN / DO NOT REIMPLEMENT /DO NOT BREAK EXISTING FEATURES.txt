- some images load slowly,
- future admin-added images must NOT make the website progressively slower.

→ validation
→ storage
→ database media reference
→ content/review/dish/gallery reference
→ public URL generation
→ static serving
→ cache headers
→ browser rendering

Do NOT assume the existing implementation is correct.

6. Preview and live/public rendering use the same valid media URL.
7. No stale browser/cache response prevents a newly uploaded image from appearing.
8. Image survives server restart.
9. Image survives a fresh server process.
10. Image is not dependent on /tmp or ephemeral storage.
11. Existing images continue working.
12. Existing content without uploaded images is unaffected.
